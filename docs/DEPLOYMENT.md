## System Requirements

### Minimum Requirements

- **OS**: Linux (Ubuntu 20.04+), Windows Server 2019+, or macOS 12+
- **CPU**: 2 cores
- **RAM**: 4 GB
- **Disk**: 20 GB SSD
- **Network**: Public IP with ports 25, 465, 587, 143, 993, 80, 443 available

### Recommended Requirements

- **CPU**: 4+ cores
- **RAM**: 8+ GB
- **Disk**: 100+ GB NVMe SSD
- **Network**: Dedicated IP with reverse DNS (PTR) record

### DNS Requirements

Before deploying, ensure you have:

1. **A Record**: `mail.example.com` → Your server IP
2. **MX Record**: `example.com` → `mail.example.com` (priority 10)
3. **PTR Record**: Your IP → `mail.example.com` (reverse DNS)
4. **SPF Record**: `v=spf1 mx ~all`
5. **DKIM**: Will be generated by uMailServer after setup
6. **DMARC**: `v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com`

## Installation

### Binary Installation

```bash
# Download the latest release
curl -L -o umailserver.tar.gz https://github.com/umailserver/umailserver/releases/latest/download/umailserver-linux-amd64.tar.gz
tar -xzf umailserver.tar.gz
sudo mv umailserver /usr/local/bin/
sudo chmod +x /usr/local/bin/umailserver

# Create data directory
sudo mkdir -p /var/lib/umailserver
sudo mkdir -p /etc/umailserver
```

### Docker Installation

```bash
# Pull the image
docker pull umailserver/umailserver:latest

# Run with docker-compose
cat > docker-compose.yml << 'EOF'
version: '3.8'
services:
  umailserver:
    image: umailserver/umailserver:latest
    container_name: umailserver
    restart: unless-stopped
    ports:
      - "25:25"      # SMTP
      - "465:465"    # SMTPS
      - "587:587"    # Submission
      - "143:143"    # IMAP
      - "993:993"    # IMAPS
      - "995:995"    # POP3S (implicit TLS; disabled unless pop3.enabled: true)
      - "4190:4190"  # ManageSieve
      - "443:443"    # Webmail + REST API (admin panel is also served here)
    volumes:
      - ./data:/var/lib/umailserver
      - ./config:/etc/umailserver
    environment:
      - UMAILSERVER_SERVER_HOSTNAME=mail.example.com
EOF

docker-compose up -d
```

### Kubernetes (Helm)

The chart in `deploy/helm/umailserver` runs the server as a StatefulSet with
exactly one pod. The accounts, mail index and IMAP metadata live in bbolt
databases, which one process holds locked, so the server cannot be scaled
out or autoscaled; an update stops the old pod before the new one starts.

```bash
helm install mail deploy/helm/umailserver \
  --namespace mail --create-namespace \
  --set hostname=mail.example.com \
  --set tls.secretName=mail-example-com-tls
```

| Value | Default | Meaning |
|-------|---------|---------|
| `hostname` | (required) | `server.hostname`; the name the certificate must cover |
| `tls.secretName` | `""` | A `kubernetes.io/tls` Secret, e.g. from cert-manager. Without it IMAP and POP3 refuse logins, 465 is not served and the web UI is plain HTTP |
| `jwtSecret` / `existingSecret` | generated | The JWT signing secret. A generated one is kept across upgrades |
| `ports.<name>.enabled` | see `values.yaml` | Which listeners the Service exposes (`smtp`, `submission`, `submissions`, `imap`, `imaps`, `pop3s`, `https`, `managesieve`) |
| `service.type` | `LoadBalancer` | |
| `service.externalTrafficPolicy` | `Local` | Keeps client IPs, which SPF, RBL checks, greylisting and rate limits need |
| `persistence.size` | `10Gi` | Volume for `/var/lib/umailserver` (mail, databases); `existingClaim` uses your own PVC |
| `config` | `{}` | Any other settings from `umailserver.yaml.example`, written into the config file |

The chart sets the host name, data directory, listener addresses, TLS file
paths and metrics listener itself, overriding the same keys in `config`. The
container binds unprivileged ports (2525, 2587, 2465, 2143, 2993, 2995, 4443)
and the Service maps them to the standard ones. Liveness uses `/healthz` on
the metrics port (8080), which is not exposed by the Service.

Back up the volume as described in [Backup & Recovery](#backup--recovery).

#### Failover

The server is not replicated; availability comes from Kubernetes starting the
pod again elsewhere (see `docs/HA_DESIGN.md`, option A).

- **Pod or process crash, rolling update, node drain:** the pod restarts or
  moves on its own. A terminating pod is removed from the Service at once
  and keeps serving for `shutdownDelaySeconds` (the `preStop` delay) while
  load balancers catch up; then the server stops, `/health/ready` answers
  503 for the rest of the shutdown, and SMTP sessions get up to
  `server.force_close_after` to finish.
- **Node failure:** Kubernetes does not move a StatefulSet pod off a node it
  cannot reach, because it cannot tell a dead node from a partitioned one
  that might still be writing to the volume. Once you have confirmed the
  node is down (powered off, or removed from the network), release the pod
  with the out-of-service taint (Kubernetes 1.28+):

  ```bash
  kubectl taint nodes <node> node.kubernetes.io/out-of-service=nodeshutdown:NoExecute
  ```

  or by deleting the Node object. The volume is then detached and the pod
  starts on another node. Remove the taint when the node is back.
- **Storage:** the pod can only move if its volume can attach on another
  node (cloud block storage, Ceph RBD, Longhorn, ...). A node-local volume
  (`local-path`, `hostPath`) ties the server to that node. Never use a
  `ReadWriteMany` volume: two nodes opening the bbolt databases corrupts them,
  which is why the chart refuses that access mode.
- **Inbound mail during an outage** is not lost: sending servers queue and
  retry for several days.

## Configuration

### Initial Setup

```bash
# Generate initial config and first domain/account
umailserver quickstart you@example.com

# Or manually create config
cat > /etc/umailserver/umailserver.yaml << 'EOF'
server:
  hostname: mail.example.com
  data_dir: /var/lib/umailserver

tls:
  acme:
    enabled: true
    email: admin@example.com
    provider: letsencrypt
    challenge: http-01   # accepted for compatibility; issuance uses TLS-ALPN-01 on the HTTPS port

smtp:
  inbound:
    enabled: true
    port: 25
    bind: 0.0.0.0
    max_message_size: 50MB
    max_recipients: 100
    max_connections: 100
  submission:
    enabled: true
    port: 587
    bind: 0.0.0.0
    require_auth: true
    require_tls: true
  submission_tls:
    enabled: true
    port: 465
    bind: 0.0.0.0
    require_auth: true

imap:
  enabled: true
  port: 993
  bind: 0.0.0.0
  max_connections: 100

pop3:
  enabled: true               # off by default
  port: 995
  bind: 0.0.0.0
  max_connections: 100

http:
  enabled: true
  port: 443
  bind: 0.0.0.0
  trusted_proxies: []         # reverse proxies allowed to set X-Forwarded-For (see SECURITY.md)

admin:
  enabled: true
  port: 8443                  # admin panel only; keep on loopback
  bind: 127.0.0.1

security:
  max_login_attempts: 5
  lockout_duration: 15m
  jwt_secret: "change-this-to-32-char-secret"

logging:
  level: info
  format: json
  output: /var/log/umailserver/umailserver.log
  max_size_mb: 100
  max_backups: 10
  max_age_days: 30

metrics:
  enabled: true
  port: 8080                  # Prometheus text format (+ /healthz); loopback by default
  bind: 127.0.0.1
  path: /metrics
EOF

# Domains and accounts live in the database, not in the YAML file. These
# commands use the file given with --config, else $UMAILSERVER_CONFIG,
# ./umailserver.yaml or /etc/umailserver/umailserver.yaml. Without any config
# they fall back to the default database in ~/.local/share/umailserver.
umailserver domain add example.com --config /etc/umailserver/umailserver.yaml
umailserver account add admin@example.com --config /etc/umailserver/umailserver.yaml
```

### Security Hardening

1. **Generate strong JWT secret**:
```bash
openssl rand -base64 32
```

2. **Set proper file permissions**:
```bash
sudo chmod 600 /etc/umailserver/umailserver.yaml
sudo chown -R umailserver:umailserver /var/lib/umailserver
```

3. **Configure firewall**:
```bash
# UFW (Ubuntu)
sudo ufw allow 25/tcp
sudo ufw allow 465/tcp
sudo ufw allow 587/tcp
sudo ufw allow 143/tcp
sudo ufw allow 993/tcp
sudo ufw allow 995/tcp    # only when pop3.enabled: true
sudo ufw allow 4190/tcp   # ManageSieve
sudo ufw allow 443/tcp    # Webmail + REST API (this port is your TLS-terminating proxy)

# Admin panel (8443), metrics (8080) and MCP (3000) bind to 127.0.0.1 by
# default: do not open them
sudo ufw deny 8443/tcp
```

## Running the Server

### Systemd Service

Create `/etc/systemd/system/umailserver.service`:

```ini
[Unit]
Description=uMailServer Email Server
After=network.target

[Service]
Type=simple
User=umailserver
Group=umailserver
ExecStart=/usr/local/bin/umailserver serve --config /etc/umailserver/umailserver.yaml
ExecReload=/bin/kill -HUP $MAINPID
Restart=always
RestartSec=5

# Security hardening
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/umailserver /var/log/umailserver

# Resource limits
LimitNOFILE=65535
LimitNPROC=4096

[Install]
WantedBy=multi-user.target
```

Enable and start:
```bash
sudo systemctl daemon-reload
sudo systemctl enable umailserver
sudo systemctl start umailserver
sudo systemctl status umailserver
```

### Environment Variables

You can override config values using environment variables:

```bash
export UMAILSERVER_SERVER_HOSTNAME=mail.example.com
export UMAILSERVER_SECURITY_JWT_SECRET="your-secret-key"
export UMAILSERVER_LOGGING_LEVEL=debug
```

## Monitoring & Alerting

### Health Checks

uMailServer provides health endpoints:

On the web listener (`http.port`, default 443; plain HTTP, unauthenticated, exempt
from rate limiting):

- `GET /health` - Full health check (503 when unhealthy)
- `GET /health/ready` - Readiness probe (503 while shutting down)

There is no `/health/live` route on that listener. The web port serves HTTPS itself when `tls.cert_file`/`tls.key_file` are set or ACME is enabled, and plain HTTP otherwise; a reverse proxy in front is optional (see SECURITY_HARDENING.md). On the separate metrics
listener (`metrics.bind:port`, default `127.0.0.1:8080`, unauthenticated):

- `GET /metrics` (`metrics.path`) - Prometheus text format
- `GET /healthz` - Liveness probe (always `200 ok`)

`GET /metrics` and `GET /api/v1/metrics` on the web listener are admin-only
JSON, not the Prometheus format. Point a container health check at
`http://localhost:443/health` or at the
`/healthz` URL above, not at `http://localhost:8080/health`.

### Prometheus Configuration

```yaml
scrape_configs:
  - job_name: 'umailserver'
    static_configs:
      - targets: ['localhost:8080']
    metrics_path: /metrics
```

### Alerting Configuration

Enable alerting in config:


## Distributed Tracing

uMailServer supports OpenTelemetry distributed tracing for monitoring request flow across SMTP, IMAP, and HTTP components.

### Configuration

Enable tracing in your config:

```yaml
tracing:
  enabled: true
  service_name: "umailserver"
  exporter: "otlp"              # Options: noop, stdout, otlp
  otlp_endpoint: "localhost:4317"  # OTLP collector endpoint
  environment: "production"
  sample_rate: 0.1              # Trace 10% of requests
  attributes:
    deployment: "primary"
    region: "us-east-1"
```

### Jaeger Integration

1. **Start Jaeger**:
```bash
docker run -d --name jaeger \
  -e COLLECTOR_OTLP_ENABLED=true \
  -p 16686:16686 \
  -p 4317:4317 \
  jaegertracing/all-in-one:latest
```

2. **Configure uMailServer**:
```yaml
tracing:
  enabled: true
  exporter: "otlp"
  otlp_endpoint: "localhost:4317"
  sample_rate: 1.0
```

3. **View traces**: Open http://localhost:16686

### OpenTelemetry Collector

For production, use OpenTelemetry Collector:

```yaml
# collector-config.yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317

exporters:
  jaeger:
    endpoint: jaeger:14250
    tls:
      insecure: true

service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [jaeger]
```

### Performance Impact

Tracing overhead is minimal:
- Noop exporter: ~0% overhead
- Stdout exporter: ~1% overhead  
- OTLP exporter: ~5% overhead (async batching)

Use sampling in high-traffic environments:
```yaml
tracing:
  sample_rate: 0.01  # Trace 1% of requests
```

## Backup & Recovery

### What a backup contains

`umailserver backup <directory>` writes `umailserver_backup_<timestamp>.tar.gz`
(or `.tar.gz.enc` with `--password`) into the given directory. The archive holds
the accounts database, the mail store (`mail/messages` and `mail/mail.db`), the
outbound queue, CalDAV and CardDAV data, push (VAPID) keys, vacation state and
DKIM keys, plus a manifest with a SHA-256 hash per file.

The server keeps its databases locked while it runs, so **stop uMailServer
before taking a backup**. `umailserver backup` refuses to run against a live
server ("database ... is locked by another process") instead of writing a torn
copy.

### Automated Backups

```bash
#!/bin/bash
# /usr/local/bin/umailserver-backup.sh
set -euo pipefail

BACKUP_DIR="/backup/umailserver"
RETENTION_DAYS=30
mkdir -p "$BACKUP_DIR"

# The databases must not be open while the backup reads them.
systemctl stop umailserver
trap 'systemctl start umailserver' EXIT

umailserver backup "$BACKUP_DIR" --config /etc/umailserver/umailserver.yaml

find "$BACKUP_DIR" -name 'umailserver_backup_*' -mtime +$RETENTION_DAYS -delete
```

```bash
# Add to crontab (runs at 02:00; mail is unavailable for the few seconds the backup takes)
0 2 * * * /usr/local/bin/umailserver-backup.sh
```

### Restore from Backup

```bash
# Extract and verify the archive into restore_temp/ next to the data directory
umailserver restore /backup/umailserver/umailserver_backup_<timestamp>.tar.gz \
    --config /etc/umailserver/umailserver.yaml

# Stop the server and copy the restored files into the data directory
sudo systemctl stop umailserver
sudo cp -a /var/lib/restore_temp/database/. /var/lib/umailserver/
sudo cp -a /var/lib/restore_temp/messages/. /var/lib/umailserver/
sudo chown -R umailserver:umailserver /var/lib/umailserver
sudo systemctl start umailserver
```

`restore` checks every file hash and the gzip checksum before it publishes
`restore_temp/`; it never writes into the live data directory itself. The
example paths assume `server.data_dir: /var/lib/umailserver`.

## Troubleshooting

### Common Issues

#### Cannot receive emails

1. Check DNS records: `dig MX example.com`
2. Verify port 25 is open: `telnet mail.example.com 25`
3. Check reverse DNS: `dig -x YOUR_IP`
4. Review logs: `journalctl -u umailserver -f`

#### TLS certificate issues

1. Check ACME status: `umailserver status`
2. Verify port 443 is reachable from the internet: ACME uses TLS-ALPN-01 on the HTTPS port. uMailServer does not listen on port 80 (`http.http_port` is reserved, not bound) and has no DNS-01 support; if 443 cannot be exposed, use manual certificates (`tls.cert_file`/`tls.key_file`) and `SIGHUP` to re-check them
3. Check certificate: `openssl s_client -connect mail.example.com:465`

#### High memory usage

1. Check queue: `umailserver queue list`
2. Review connections: `netstat -an | grep :25 | wc -l`
3. Check process memory with `ps -o rss -p $(pgrep -x umailserver)` and the metrics on `127.0.0.1:8080/metrics`

### Log Locations

- **Application logs**: `/var/log/umailserver/umailserver.log`
- **System logs**: `journalctl -u umailserver`
- **Mail logs**: `/var/lib/umailserver/logs/`

### Debug Mode

```bash
# Run with debug logging
umailserver --config /etc/umailserver/umailserver.yaml --log-level debug

# Or set environment variable
export UMAILSERVER_LOGGING_LEVEL=debug
```

### Performance Tuning

1. **Increase file descriptors**:
```bash
ulimit -n 65535
```

2. **Kernel tuning** (Linux):
```bash
# /etc/sysctl.conf
net.ipv4.tcp_keepalive_time = 300
net.ipv4.tcp_keepalive_probes = 5
net.ipv4.tcp_keepalive_intvl = 15
net.core.somaxconn = 65535
```

3. **Database optimization**:
```yaml
database:
  sync: false  # Disable fsync for better performance (risk of data loss on crash)
```

## Production Checklist

Before going live:

- [ ] DNS records configured (A, MX, PTR, SPF, DKIM, DMARC)
- [ ] TLS certificates configured (Let's Encrypt or manual)
- [ ] Firewall rules applied
- [ ] Backup system configured
- [ ] Monitoring and alerting enabled
- [ ] Log rotation configured
- [ ] Rate limiting enabled
- [ ] JWT secret is strong (32+ chars)
- [ ] Admin panel restricted to localhost/VPN
- [ ] Tested email flow (send/receive)
- [ ] Tested authentication (IMAP/SMTP)
- [ ] Reviewed security settings
